# 프로그래머스 풀이를 읽지 못했을 때

> **Description**: 정답은 받았지만 풀이를 저장소에 올릴 수 없을 때 사용자가 무엇을 보게 되는지를 정의한다. 정답을 세는 규칙은 [프로그래머스 정답 감지](programmers-accepted-detection.md)를 따른다.

## Goal
정답을 받았는데 풀이를 저장소에 올리지 못한 경우, 조용히 넘어가지 않고 사용자가 그 사실을 알게 한다.

## Triggers
- 정답을 센 뒤 문제 번호, 문제 이름, 언어 중 하나라도 비어 있거나 편집기의 코드가 비어 있을 때
- 정답을 센 뒤 고른 언어가 이 확장 프로그램이 다루는 언어 목록에 없을 때

## Inputs
- 정답을 센 순간 고정한 풀이 묶음 — 그 안에 빠진 값이 있는지가 판단 근거다.
- 이 확장 프로그램이 다루는 언어 목록 — 제품이 정하며 사용자가 바꿀 수 없다.

## Outputs
- 읽지 못한 경우: 화면 구석에 실패했다는 알림이 뜨고 편집기의 코드를 읽지 못했다는 안내가 함께 보인다. 기록 목록에 실패한 줄이 하나 남고, 커밋은 생기지 않는다.
- 다루지 않는 언어인 경우: 그 언어는 저장하지 않는다는 안내가 보이고 기록 목록에 한 줄이 남는다. 커밋은 생기지 않는다.
- 두 경우 모두 **다시 시도하는 버튼을 제공하지 않는다.** 다시 올리려면 사용자가 문제를 다시 제출해야 한다.
- 실패한 줄에도 어느 문제였는지 알 수 있도록 문제 번호와 이름이 남는다.

## Edge cases
- 코드가 공백이나 줄바꿈만 있으면 비어 있는 것으로 본다.
- 문제 이름을 화면에서 찾지 못해도 문제 번호가 이름 자리를 대신하므로, 이름 때문에 실패하는 경우는 사실상 생기지 않는다.
- 저장소를 아직 연결하지 않았거나 자동으로 올리는 설정을 꺼 둔 경우는 이 실패가 아니다. 그때는 설정을 확인하라는 다른 안내가 보인다.
- 실패한 뒤 같은 문제를 다시 제출해 이번에는 제대로 읽히면, 그 제출은 평소대로 커밋이 된다.
- 실패해도 정답을 셌다는 사실 자체는 남지 않는다. 같은 풀이를 다시 제출하면 중복으로 걸리지 않고 다시 시도된다.

## Acceptance
- 이 확장 프로그램이 다루지 않는 언어로 정답을 받으면, 그 언어는 저장하지 않는다는 안내가 보인다
- 다루지 않는 언어로 정답을 받은 뒤 저장소를 열어 보면, 새 커밋이 없다
- 다루지 않는 언어로 정답을 받은 뒤 기록 목록을 열면, 그 제출에 대한 줄이 하나 남아 있다
- 풀이를 읽지 못해 실패한 줄을 기록 목록에서 열면, 다시 시도하는 버튼이 없다
- 실패한 줄을 기록 목록에서 보면, 어느 문제였는지 알 수 있는 번호와 이름이 함께 보인다

## 열린 질문
- 다시 시도하는 버튼을 제공하지 않는 것은 편집기 내용을 보관하지 않기로 한 결정 때문인가? 사용자에게는 "다시 제출하세요"라는 안내가 더 필요하지 않은가?
- 편집기의 코드를 읽지 못하는 상황이 실제로 어떤 경우에 생기는지 확인된 적이 있는가? 지금까지는 짐작만 있다.
