# 풀이의 저장 위치와 목록

> **Description**: 정답이 사용자의 저장소 어디에 어떤 이름으로 쌓이고 목록에 어떻게 보이는지를, 세 사이트 공통으로 정의한다. 사이트마다 다른 것은 이 문서 안의 차이 표에 모았다.

## Goal
어느 사이트에서 푼 풀이든 저장소에서 사이트별·언어별로 정리되어 쌓이고, 한 장의 목록으로 한눈에 보이게 한다.

## Triggers
정답이 저장소에 올라갈 때마다.

## Inputs
- 문제 번호와 문제 이름 — 어느 문제를 풀었는지로 정해진다. 출처는 사이트마다 다르다.
- 고른 언어와 풀이 코드 — 사용자가 정한다.
- 목록에서 문제로 돌아가는 링크 주소 — 사이트마다 만드는 방법이 다르다.
- 그 문제를 그 언어로 올린 것이 몇 번째인지 — 확장 프로그램이 센다.
- 어느 저장소의 어느 가지에 올릴지 — 사용자가 설정 화면에서 고른다.
- 난이도 — 알려주는 사이트에서만 들어온다.

## Outputs
- 저장소 최상위에 사이트별 폴더가 생기고, 그 안에서 언어별로 폴더가 나뉜다.
- 풀이 파일 이름은 문제 번호와 문제 이름을 밑줄로 이은 형태이며, 언어에 맞는 확장자가 붙는다.
- 사이트 폴더 안에 목록 문서가 생긴다. 문제 하나가 한 줄이고, 여러 언어로 푼 문제는 한 칸에 링크가 여럿 들어간다.
- 목록의 줄은 그 문제를 처음 푼 날짜가 최근인 것부터 놓이고, 같은 날짜끼리는 문제 번호 순으로 놓인다. 날짜 칸에 보이는 것도 처음 푼 날짜라 목록 순서와 날짜가 어긋나지 않는다.
- 목록 문서에서 확장 프로그램이 관리하는 구간은 표시로 감싸여 있고, 사용자가 그 밖에 직접 쓴 내용은 갱신할 때도 그대로 남는다.
- 사이트 폴더 안 숨김 폴더에 목록의 원본 자료 파일이 함께 쌓인다.
- 커밋 한 번에 풀이 파일, 목록 문서, 원본 자료가 함께 바뀐다.
- 커밋 설명에는 사이트 이름, 문제 번호, 문제 이름, 언어와 몇 번째 풀이인지가 사람이 읽을 수 있는 한 줄로 들어간다.

## 사이트마다 다른 것

| | LeetCode | Programmers | SW Expert Academy |
|---|---|---|---|
| 파일 이름의 번호 | **네 자리가 되도록 앞을 영으로 채운다** | 화면에 보이는 그대로 | 화면에 보이는 그대로 |
| 파일 이름의 문제 이름 | 모두 소문자가 되고 영문자와 숫자가 아닌 것은 밑줄로 바뀐다 | 한글은 그대로 남고 빈칸과 기호는 밑줄로 바뀐다 | 한글은 그대로 남고 빈칸과 기호는 밑줄로 바뀐다 |
| 난이도 칸 | **있다.** 사이트가 알려준 값이 그대로 들어간다 | 없다. 사이트가 알려주지 않는다 | 없다. 풀이 화면에 없어 가져오지 않는다 |
| 목록의 문제 링크 | 사이트가 알려준 문제 주소 | 문제 화면 주소에서 뒤의 부가 표시를 뗀 것 | **문제 소개 화면.** 풀이 화면 주소가 모든 문제에서 같아 쓸 수 없다 |
| 언어별 폴더 | 다루는 언어 전부 | 다루는 언어 전부 | 실제로 쓰이는 것은 세 언어뿐 |
| 번호를 읽지 못했을 때 | 숫자가 아니면 앞을 채우지 않고 소문자 밑줄 형태로 바꿔 쓴다 | 해당 없음 | 화면 안의 문제 식별 값이 번호 자리에 들어간다 |

## Edge cases
- 같은 문제를 두 언어로 풀면 목록에는 줄이 하나만 늘고, 그 줄의 링크 칸에 언어가 둘 들어간다.
- 같은 문제를 같은 언어로 다시 풀어 코드가 달라지면 파일은 새 내용으로 바뀌고, 몇 번째 풀이인지가 하나 올라간다.
- 문제 이름을 파일 이름으로 쓸 수 없으면 밑줄로 바뀌고, 그러고도 남는 글자가 없으면 정해진 기본 이름이 쓰인다.
- 커밋 설명의 문제 번호는 앞을 영으로 채우지 않고 원래 번호 그대로 쓴다. 그래서 LeetCode에서는 파일 이름과 커밋 설명의 번호 표기가 서로 다르다.
- 커밋 설명에서 문제 이름의 따옴표는 지워지고 이어진 빈칸은 하나로 줄어든다. 그러고 남는 것이 없으면 정해진 기본 이름이 쓰인다.
- 커밋 설명에 몇 번째 풀이인지를 적을 때 우물 정자 기호를 쓰지 않는다. 저장소에 등록된 다른 글의 번호로 잘못 이어지기 때문이다.
- 문제 이름이 대괄호로 시작해도 목록의 링크가 깨지지 않는다.
- 사용자가 목록 문서의 관리 구간 안을 손으로 고쳐 두면, 다음 커밋에서 그 구간은 다시 만들어져 손댄 내용이 사라진다.
- 목록 문서에 관리 구간 표시가 아예 없으면 문서 맨 끝에 새로 붙는다.
- 저장소에 목록 문서가 아직 없으면 사이트마다 정해진 제목 한 줄이 붙은 새 문서가 만들어지고 그 아래에 관리 구간이 놓인다.
- 올리는 사이에 다른 커밋이 먼저 올라가 부딪히면, 저장소의 최신 내용을 다시 읽어 목록을 다시 만든 뒤 올린다.

## Acceptance
- 어느 사이트에서든 정답을 받은 뒤 저장소를 열면, 그 사이트 폴더 안 언어별 폴더에 풀이 파일이 있다
- 그 파일 이름을 보면 문제 번호와 문제 이름이 밑줄로 이어져 있다
- LeetCode에서 두 자리 번호의 문제를 풀고 파일 이름을 보면, 번호 앞이 영으로 채워져 네 자리로 되어 있다
- LeetCode 목록 문서를 열면 난이도 칸이 있다
- Programmers 목록 문서를 열면 난이도 칸이 없다
- 서로 다른 날에 두 문제를 풀고 목록 문서를 열면, 나중에 푼 문제가 위에 있다
- 같은 문제를 두 언어로 풀고 목록 문서를 열면, 그 문제 줄은 하나이고 링크가 둘이다
- 목록 문서의 관리 구간 밖에 직접 글을 써 두고 새 풀이를 올리면, 써 둔 글이 그대로 남아 있다
- 같은 문제를 같은 언어로 두 번 풀고 커밋 설명을 보면, 두 번째 설명에 두 번째 풀이라는 표시가 들어 있다
- 정답 하나로 만들어진 커밋을 열면 풀이 파일과 목록 문서가 함께 바뀌어 있다
- 목록 문서의 문제 링크를 누르면 그 문제 화면이 열린다

## 열린 질문
- 파일 이름의 번호는 LeetCode에서만 네 자리로 채우고 커밋 설명에서는 채우지 않는다. 한 사이트 안에서 두 표기가 다른 것이 혼란이 되지 않는가?
- 문제 번호가 네 자리를 넘는 문제에서는 파일 이름의 자릿수가 들쭉날쭉해진다. 정렬을 위해 채우는 것인데 그 목적이 유지되는가?
- 숨김 폴더의 원본 자료 파일은 사용자가 직접 볼 일이 없는데도 저장소에 남는다. 이것이 의도된 결정인가?
- 목록 문서의 관리 구간 안을 사용자가 고쳤을 때 그 내용이 사라지는 것을 사용자에게 미리 알릴 필요가 있는가?
- SW Expert Academy는 세 언어만 제공하는데 언어별 폴더 규칙은 다루는 언어 전부에 준비되어 있다. 쓰이지 않는 폴더 규칙을 남겨 두는 것이 의도된 것인가?
