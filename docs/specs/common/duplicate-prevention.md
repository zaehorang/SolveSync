# 같은 풀이 중복 방지

> **Description**: 하나의 정답이 두 번 저장되지 않게 막는 규칙을 세 사이트 공통으로 정의한다. **막는 것은 "같은 정답이 두 번 처리되는 것"이고, "같은 코드를 다시 제출하는 것"이 아니다.** 같은 코드를 다시 제출하면 커밋이 하나 더 생긴다.

## Goal
정답 하나가 실수로 두 번 저장되지 않게 한다. 사용자가 다시 푼 것까지 막지는 않는다.

## Triggers
올릴 내용을 확정한 뒤 저장소에 올리기 직전마다 매번 확인한다.

## Inputs
- 어느 문제인지, 어떤 언어인지 — 사용자가 정한다.
- 그 정답을 가리키는 값 — LeetCode는 사이트가 제출마다 붙이는 **제출 번호**를 쓰고, 나머지 두 사이트는 번호가 없으므로 **정답을 확인한 시각**을 쓴다. 어느 쪽이든 정답 하나에 하나씩 붙고, 다시 제출하면 다른 값이 된다.
- 지금까지 저장소에 올리는 데 **성공한** 열쇠 목록 — 확장 프로그램이 기기 안에 보관한다. 최근 100개까지, 7일 동안 보관한다.
- 지금 저장하는 중인 열쇠 목록 — 확장 프로그램이 기기 안에 보관하며 10분이 지나면 저절로 풀린다.

## Outputs
- 처음 보는 정답이면 저장소에 올리는 작업이 그대로 진행된다.
- 같은 정답이 또 들어오면 **아무 일도 일어나지 않는다.** 알림도 뜨지 않고, 기록 목록에도 줄이 늘지 않으며, 커밋도 생기지 않는다.
- 성공한 열쇠 목록에는 저장소에 커밋이 실제로 만들어진 뒤에만 추가된다.

## 세 사이트가 같다

무엇으로 정답을 가려내는지는 사이트마다 다르지만 **사용자가 겪는 결과는 같다.**

| | LeetCode | Programmers · SW Expert Academy |
|---|---|---|
| 무엇으로 정답 하나를 가리나 | 사이트가 붙이는 제출 번호 | 정답을 확인한 시각 |
| 같은 코드를 그대로 다시 제출하면 | 커밋이 하나 더 생긴다 | 커밋이 하나 더 생긴다 |
| 막히는 경우 | 같은 정답을 두 번 집어 들었을 때뿐 | 같은 정답을 두 번 집어 들었을 때뿐 |

커밋이 하나 더 생길 때 **파일 내용은 그대로지만 풀이 회차가 하나 올라간다.** 목록에 적히는 마지막 정답 날짜도 갱신된다.

## Edge cases
- 같은 코드라도 언어가 다르면 다른 풀이로 본다. 파일도 따로 만들어진다.
- 같은 코드라도 다른 문제에서 제출했으면 다른 풀이로 본다. SW Expert Academy처럼 두 문제의 주소가 똑같아도 그렇다.
- 저장소에 올리다가 실패하면 성공한 열쇠 목록에 남지 않는다. 그래서 다시 제출하면 그때는 다시 시도된다.
- 앞의 것이 아직 올라가는 중인데 같은 것이 또 들어오면 뒤엣것은 조용히 버려진다. 앞의 것이 10분 안에 끝나지 않으면 그 잠금은 저절로 풀린다.
- 확장 프로그램을 지우고 다시 설치하면 성공한 열쇠 목록도 함께 사라진다. 그 뒤에는 예전에 올렸던 것도 처음 보는 것으로 취급된다.
- 성공한 열쇠 목록은 100개를 넘거나 7일이 지나면 오래된 것부터 사라진다. 그보다 앞선 정답이 어떤 이유로 다시 들어오면 막지 못한다.
- 다루지 않는 언어로 한 제출은 이 확인에 이르기 전에 걸러진다.
- SW Expert Academy는 문제당 제출 횟수에 상한이 있다. 같은 코드를 반복 제출하면 커밋은 매번 생기지만 남은 횟수도 함께 줄어든다.
- 이미 푼 문제 화면을 여는 것만으로 정답이 잘못 감지되면 그대로 커밋이 하나 생긴다. 예전에는 같은 코드가 걸러져 우연히 막히는 경우가 있었으나 이제는 막히지 않는다. 잘못 감지되는 것 자체를 막는 일은 [정답 감지](../leetcode/accepted-detection.md) 쪽에 있다.

## Acceptance
- Programmers에서 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 하나 더 생긴다
- 그렇게 생긴 커밋의 설명을 보면, 풀이 회차가 하나 올라가 있다
- SW Expert Academy에서 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 하나 더 생긴다
- LeetCode에서 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 하나 더 생긴다
- 코드에 주석 한 줄을 더해 다시 제출해 정답을 받으면, 새 커밋이 하나 생긴다
- 같은 코드를 다른 언어로 옮겨 제출해 정답을 받으면, 새 커밋이 하나 생긴다
- 저장소 연결이 끊긴 채로 정답을 받아 실패한 뒤 연결을 고치고 같은 문제를 다시 제출하면, 이번에는 커밋이 생긴다
- 이미 저장한 적이 있는 문제 화면을 다시 열어 두기만 하면, 커밋이 생기지 않는다

## 열린 질문
- 확장 프로그램을 다시 설치했을 때 예전 풀이가 다시 올라가는 것은 의도된 동작인가? 저장소에는 같은 내용의 커밋이 하나 더 쌓인다.
- 저장하는 중이라는 잠금이 10분 뒤 풀리는 것은 무엇을 근거로 정한 값인가? 그 사이 브라우저를 껐다 켜면 잠금이 남아 있는 동안 같은 것을 저장할 수 없는데, 사용자에게 그 사실이 보이지 않는다.
- 같은 문제를 여러 번 풀면 저장소에 커밋이 그만큼 쌓인다. 사용자가 그 기록을 정리하고 싶어질 때 확장 프로그램이 도울 일이 있는가?
