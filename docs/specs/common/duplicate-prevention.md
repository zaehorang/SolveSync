# 같은 풀이 중복 방지

> **Description**: 이미 저장한 것이 다시 올라왔을 때 같은 커밋이 다시 쌓이지 않는 규칙을 세 사이트 공통으로 정의한다. **무엇을 "같은 것"으로 보는지는 사이트마다 다르고, 그 차이가 사용자에게 정반대의 결과로 나타난다.**

## Goal
이미 저장한 것이 다시 올라와도 저장소에 같은 커밋이 다시 쌓이지 않게 한다.

## Triggers
올릴 내용을 확정한 뒤 저장소에 올리기 직전마다 매번 확인한다.

## Inputs
- 어느 문제인지, 어떤 언어인지 — 사용자가 정한다.
- 그 풀이를 가리키는 값 — **무엇이 이 자리에 들어가는지가 사이트마다 다르다.** 아래 차이 표를 따른다.
- 지금까지 저장소에 올리는 데 **성공한** 열쇠 목록 — 확장 프로그램이 기기 안에 보관한다.
- 지금 저장하는 중인 열쇠 목록 — 확장 프로그램이 기기 안에 보관하며 10분이 지나면 저절로 풀린다.

## Outputs
- 처음 보는 것이면 저장소에 올리는 작업이 그대로 진행된다.
- 이미 올린 것과 같으면 **아무 일도 일어나지 않는다.** 알림도 뜨지 않고, 기록 목록에도 줄이 늘지 않으며, 커밋도 생기지 않는다.
- 성공한 열쇠 목록에는 저장소에 커밋이 실제로 만들어진 뒤에만 추가된다.

## 사이트마다 다른 것

| | LeetCode | Programmers · SW Expert Academy |
|---|---|---|
| 무엇으로 같은지 판단하나 | 사이트가 제출마다 붙이는 **제출 번호** | 문제, 언어와 **코드 내용** |
| 같은 코드를 그대로 다시 제출하면 | **커밋이 하나 더 생긴다.** 제출 번호가 새로 붙기 때문이다. 파일 내용은 그대로지만 풀이 회차가 하나 올라간다 | 커밋이 생기지 않는다 |
| 막히는 경우 | 같은 제출을 두 번 집어 들었을 때뿐. 정답 신호가 두 번 왔는데 그 사이 새 제출이 없었던 경우다 | 문제·언어·코드가 모두 같을 때 |

**같은 저장소 안에서 규칙이 갈린다.** LeetCode 폴더에는 내용이 같은 커밋이 쌓일 수 있고, 나머지 두 폴더에는 쌓이지 않는다.

## Edge cases
- 코드 내용으로 판단하는 사이트에서는 코드가 한 글자라도 다르면 다른 풀이로 본다. 공백이나 줄바꿈만 달라도 다르다.
- 같은 코드라도 언어가 다르면 다른 풀이로 본다.
- 같은 코드라도 다른 문제에서 제출했으면 다른 풀이로 본다. SW Expert Academy처럼 두 문제의 주소가 똑같아도 그렇다.
- 저장소에 올리다가 실패하면 성공한 열쇠 목록에 남지 않는다. 그래서 다시 제출하면 그때는 다시 시도된다.
- 앞의 것이 아직 올라가는 중인데 같은 것이 또 들어오면 뒤엣것은 조용히 버려진다. 앞의 것이 10분 안에 끝나지 않으면 그 잠금은 저절로 풀린다.
- 확장 프로그램을 지우고 다시 설치하면 성공한 열쇠 목록도 함께 사라진다. 그 뒤에는 예전에 올렸던 것도 처음 보는 것으로 취급된다.
- 성공한 열쇠 목록은 지워지거나 오래됐다고 버려지지 않고 계속 쌓인다.
- 다루지 않는 언어로 한 제출은 이 확인에 이르기 전에 걸러진다.
- SW Expert Academy에서는 커밋이 생기지 않아도 사이트의 제출 횟수는 소모된다. 문제당 제출 횟수에 상한이 있으므로, 새 커밋을 만들려고 같은 코드를 반복 제출하면 횟수만 줄어든다.
- LeetCode에서 이미 푼 문제를 열었을 때 잘못 감지되는 경우가 있더라도, 그 문제의 마지막 정답 제출을 이 기기에서 이미 저장한 적이 있으면 여기서 막힌다. 확장 프로그램을 설치하기 전에 푼 문제만 이 방어를 지나친다.

## Acceptance
- Programmers에서 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 생기지 않는다
- 그렇게 다시 제출해 정답을 받으면, 저장소로 올린다는 알림도 보이지 않는다
- LeetCode에서 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 하나 더 생긴다
- LeetCode에서 그렇게 다시 제출한 뒤 커밋 설명을 보면, 풀이 회차가 하나 올라가 있다
- 코드에 주석 한 줄을 더해 다시 제출해 정답을 받으면, 새 커밋이 하나 생긴다
- 같은 코드를 다른 언어로 옮겨 제출해 정답을 받으면, 새 커밋이 하나 생긴다
- 저장소 연결이 끊긴 채로 정답을 받아 실패한 뒤 연결을 고치고 같은 문제를 다시 제출하면, 이번에는 커밋이 생긴다
- 한 번의 정답 제출로 알림이 두 번 뜨는 경우에도 기록 목록에는 줄이 하나만 남는다
- 이미 저장한 적이 있는 문제 화면을 다시 열어 두기만 하면, 커밋이 생기지 않는다

## 열린 질문
- 같은 코드를 다시 제출했을 때 LeetCode에서만 커밋이 하나 더 생기는 것은 의도된 결정인가? 같은 저장소 안에서 폴더마다 규칙이 갈린다.
- 같은 코드를 다시 제출해 아무 알림도 보이지 않을 때, 사용자는 확장 프로그램이 동작하지 않은 것인지 중복이라 건너뛴 것인지 구분할 수 없다. 알려 주어야 하는가?
- 확장 프로그램을 다시 설치했을 때 예전 풀이가 다시 올라가는 것은 의도된 동작인가? 저장소에는 같은 내용의 커밋이 하나 더 쌓인다.
- 성공한 열쇠 목록은 개수 제한도 보관 기간 제한도 없이 계속 쌓인다. 오래 쓴 기기에서 이 목록이 커지는 것이 문제가 되는가?
- 저장하는 중이라는 잠금이 10분 뒤 풀리는 것은 무엇을 근거로 정한 값인가? 그 사이 브라우저를 껐다 켜면 잠금이 남아 있는 동안 같은 것을 저장할 수 없는데, 사용자에게 그 사실이 보이지 않는다.
