# 프로그래머스 같은 풀이 중복 방지

> **Description**: 같은 풀이를 다시 제출했을 때 저장소에 같은 커밋이 다시 쌓이지 않는 규칙을, 화면과 저장소에서 관측되는 것만으로 정의한다. 풀이를 무엇으로 고정하는지는 [프로그래머스 풀이 확정](solution-snapshot.md)을 따른다.

## Goal
이미 저장한 것과 똑같은 풀이가 다시 올라와도 저장소에 같은 커밋이 다시 쌓이지 않게 한다.

## Triggers
정답을 세어 풀이를 고정한 뒤, 저장소에 올리기 직전마다 매번 확인한다.

## Inputs
- 문제 번호 — 사용자가 연 문제로 정해진다.
- 선택된 언어 — 사용자가 고른다.
- 코드 내용 전체 — 사용자가 쓴 그대로이며 공백과 줄바꿈까지 포함해 비교 대상이다.
- 지금까지 저장소에 올리는 데 **성공한** 목록 — 확장 프로그램이 기기 안에 보관한다.

## Outputs
- 처음 보는 풀이면 저장소에 올리는 작업이 그대로 진행된다.
- 이미 올린 것과 같은 풀이면 **아무 일도 일어나지 않는다.** 알림도 뜨지 않고, 기록 목록에도 줄이 늘지 않으며, 커밋도 생기지 않는다.
- 올린 목록에는 저장소에 커밋이 실제로 만들어진 뒤에만 추가된다.

## Edge cases
- 코드가 한 글자라도 다르면 다른 풀이로 본다. 공백이나 줄바꿈만 달라도 다른 풀이다.
- 같은 코드라도 언어가 다르면 다른 풀이로 본다.
- 같은 코드라도 다른 문제에서 제출했으면 다른 풀이로 본다.
- 저장소에 올리다가 실패하면 올린 목록에 남지 않는다. 그래서 같은 풀이를 다시 제출하면 그때는 다시 시도된다.
- 앞의 것이 아직 올라가는 중인데 같은 풀이가 또 들어오면 뒤엣것은 조용히 버려진다.
- 확장 프로그램을 지우고 다시 설치하면 올린 목록도 함께 사라진다. 그 뒤에는 예전에 올렸던 풀이도 처음 보는 것으로 취급된다.
- 지원하지 않는 언어로 제출한 경우는 이 확인에 이르기 전에 걸러진다. 그때 무엇이 보이는지는 [프로그래머스 풀이를 읽지 못했을 때](extract-failure.md)를 따른다.

## Acceptance
- 정답을 받은 뒤 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 생기지 않는다
- 코드를 그대로 두고 다시 제출해 정답을 받으면, 저장소로 올린다는 알림도 보이지 않는다
- 코드를 한 줄 고쳐 다시 제출해 정답을 받으면, 새 커밋이 하나 생긴다
- 같은 코드를 다른 언어로 제출해 정답을 받으면, 새 커밋이 하나 생긴다
- 저장소 연결이 끊긴 채로 정답을 받아 실패한 뒤 연결을 고치고 같은 코드를 다시 제출하면, 이번에는 커밋이 생긴다

## 열린 질문
- 확장 프로그램을 다시 설치했을 때 예전 풀이가 다시 올라가는 것은 의도된 동작인가? 저장소에는 같은 내용의 커밋이 하나 더 쌓인다.
- 아직 올라가는 중일 때 들어온 같은 풀이를 조용히 버리는 대신 사용자에게 알려야 하는가?
