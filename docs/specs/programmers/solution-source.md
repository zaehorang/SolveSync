# 프로그래머스 풀이 확보

> **Description**: 정답을 센 그 순간에 무엇을 읽어 고정하는지, 그 뒤의 편집이 왜 섞이지 않는지를 화면에서 관측되는 것만으로 정의한다. 정답을 세는 규칙은 [프로그래머스 정답 감지](accepted-detection.md)를 따른다.

## Goal
정답을 받은 그 순간의 풀이 내용을 그 자리에서 고정해, 그 뒤에 무엇을 고치든 저장소에는 정답을 받은 그대로 올라가게 한다.

## Triggers
새로운 정답을 센 바로 그 순간, 한 번만 읽는다. 그 뒤로는 저장소에 올리는 어느 단계에서도 화면을 다시 읽지 않는다.

## Inputs
- 편집기에 들어 있는 코드 — 사용자가 쓴 그대로다. 화면 밖으로 넘어가 보이지 않는 줄도 포함한다.
- 문제 이름 — 프로그래머스가 화면에 넣어 둔 것에서 가져온다. 공유용 제목, 브라우저 탭에 뜨는 제목, 화면의 큰 제목 순으로 찾아 처음 쓸 만한 것을 쓴다.
- 선택된 언어 — 사용자가 언어 고르는 곳에서 고른 값이다.
- 문제 화면의 주소와 문제 번호 — 사용자가 어떤 문제를 열었는지로 정해진다.
- 정답을 센 시각 — 확장 프로그램이 그 순간 기록한다.

## Outputs
- 위 다섯 가지가 한 묶음으로 고정되어 저장소에 올리는 쪽으로 넘어간다. 이 묶음은 이후 바뀌지 않는다.
- 문제 이름은 다듬어서 넘긴다. 뒤에 붙는 사이트 이름과 앞에 붙는 분류 이름을 떼어내고, 그러고 남은 것이 문제 이름이 아니라 분류 이름뿐이면 그 후보를 버리고 다음 후보로 넘어간다.
- 쓸 만한 이름을 끝내 못 찾으면 문제 번호를 이름으로 쓴다.
- 목록에 남기는 문제 링크에서는 주소 뒤에 붙은 부가 표시를 떼어낸다. 그때 보고 있던 언어가 주소에 남아 있어도 링크에는 붙지 않는다.

## Edge cases
- 정답 창이 뜬 직후 편집기를 곧바로 고쳐도, 올라가는 것은 고치기 전 코드다.
- 같은 순간에 신호가 여러 번 들어와도 처음 고정한 묶음만 쓴다. 그 사이에 편집기가 바뀌어도 섞이지 않는다.
- 편집기가 비어 있거나 공백만 있으면 이 묶음을 만들지 못하고 실패로 넘어간다. 실패했을 때 무엇이 보이는지는 [프로그래머스 풀이를 확보하지 못했을 때](source-failure.md)를 따른다.
- 화면에 보이지 않을 만큼 긴 풀이가 잘리지 않는지는 아직 실제 제출로 확인되지 않았다. 짧은 풀이에서는 편집기의 내용과 정확히 같았다.
- 언어를 고르는 곳은 화면 구조에 따라 여러 자리 중 하나일 수 있고, 실제 화면에서는 마지막 후보에서 값이 나온다.
- 문제 이름에 파일 이름으로 쓸 수 없는 문자가 있으면 밑줄로 바뀐 채 저장된다. 한글은 그대로 남는다.

## Acceptance
- 정답 창이 뜬 직후 편집기의 코드를 고치고 나서 저장소를 열면, 고치기 전 코드가 올라가 있다
- 어떤 언어를 골라 정답을 받으면 저장소에 그 언어의 파일로 올라간다
- 정답을 받은 뒤 저장소를 열면 파일 이름에 그 문제의 번호와 이름이 들어 있다
- 주소 뒤에 언어 표시가 붙은 상태에서 정답을 받아도, 목록의 문제 링크를 눌렀을 때 열리는 주소에는 그 표시가 없다
- 문제 이름을 화면에서 찾을 수 없는 문제에서 정답을 받으면 문제 번호가 이름 자리에 들어간다

## 열린 질문
- 화면 밖으로 스크롤될 만큼 긴 풀이에서도 코드가 온전히 읽히는지 실제 제출로 확인해야 한다. 잘릴 이유는 없다고 보지만 확인된 적은 없다.
- 문제 이름 후보 중 어느 것이 실제로 쓰이는지는 문제마다 다를 수 있다. 어느 후보가 주로 쓰이는지 확인해 둘 필요가 있는가?
