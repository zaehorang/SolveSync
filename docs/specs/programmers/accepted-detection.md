# 프로그래머스 정답 감지

> **Description**: 프로그래머스에서 정답을 받은 순간을 언제 새로운 정답으로 세고 언제 세지 않는지를, 화면에서 관측되는 것만으로 정의한다. 풀이 내용을 확정하는 동작은 [프로그래머스 풀이 확보](solution-source.md)을 따른다.

## Goal
프로그래머스에서 정답을 받은 순간을 한 번만 알아채, 그 풀이가 저장소로 넘어가기 시작하게 한다.

## Triggers
- 사용자가 프로그래머스 문제 풀이 화면에서 제출한 결과 창이 "정답입니다!"라는 제목을 달고 화면에 실제로 나타난 순간
- 결과 창을 닫았다가 다시 정답을 받아, 결과 창이 다시 화면에 나타난 순간

두 계기 모두 **결과 창이 눈에 보이게 된 순간**을 가리킨다. 제목 문구가 채워지기만 하고 창이 아직 보이지 않으면 계기가 아니다.

## Inputs
- 지금 열려 있는 문제 화면의 주소 — 사용자가 어떤 문제를 열었는지로 정해진다. 주소에서 강의 번호와 문제 번호를 읽으며, 두 번호를 읽을 수 없는 주소는 감지 대상이 아니다.
- 결과 창의 제목 문구 — 프로그래머스가 정한다. 앞뒤 공백을 무시했을 때 정확히 "정답입니다!"일 때만 정답으로 본다. "통과", "채점 결과", "합계: 100.0 / 100.0" 같은 다른 결과 문구는 단독으로는 정답 신호가 아니다.
- 결과 창이 눈에 보이는지 여부 — 프로그래머스가 정한다.
- 같은 순간에 온 신호를 하나로 묶는 시간 — 제품이 0.7초로 고정하며 사용자가 바꿀 수 없다.

## Outputs
- 정답으로 셀 때: 화면 구석에 저장소로 올리는 중이라는 알림이 뜨고, 뒤이어 성공 또는 실패 알림으로 바뀐다. 확장 프로그램의 기록 목록에 한 줄이 남고, 사용자가 연결한 저장소에 커밋이 하나 생긴다.
- 정답으로 세지 않을 때: 알림도, 기록도, 커밋도 생기지 않는다. 화면에는 프로그래머스가 원래 보여주는 것 말고 아무 변화가 없다.
- 한 번의 정답에 대해 알림·기록·커밋은 각각 하나씩이다.

## Edge cases
- 결과 내용이 채워지는 순간과 창이 눈에 보이게 되는 순간은 갈라져서 온다. 이때 정답으로 세는 시점은 **창이 눈에 보이게 된 뒤**이며, 정답은 그래도 한 번만 세어진다.
- 정답 창이 이미 떠 있는 동안 화면의 다른 곳이 바뀌어도 같은 정답을 다시 세지 않는다.
- 결과 창을 닫으면 아무 일도 일어나지 않고, 다음 정답을 셀 수 있는 준비만 된다.
- 틀린 제출도 같은 결과 창을 쓰고 제목만 다르다. 이때는 아무 일도 일어나지 않는다.
- 코드 실행만 한 경우, 채점이 실패한 경우, 컴파일이 실패한 경우에도 아무 일도 일어나지 않는다.
- 확장 프로그램이 켜지는 순간 정답 창이 이미 떠 있으면, 그 정답은 세지 않는다. 이미 지난 정답을 다시 올리지 않기 위해서다.
- 새로고침 없이 같은 사이트 안에서 다른 문제로 옮겨 가면, 옮겨 간 문제 번호로 다시 세기 시작한다. 옮겨 가는 순간에 정답 문구가 함께 들어오면 그 정답도 센다.
- **다른 코딩 사이트 화면에서 새로고침 없이 프로그래머스 문제 화면으로 넘어온 경우, 넘어온 직후의 첫 변화는 판정하지 않는다.** 그 순간 정답 창이 이미 보이고 있었다면 그 정답은 기록되지 않는다. 화면을 새로 고치고 다시 제출하면 정상적으로 기록된다.
- 결과 창이 통째로 다른 것으로 바뀌면, 바뀐 순간은 판정하지 않고 새 창을 기준으로 다시 세기 시작한다.
- 정답을 센 직후 0.7초 안에 들어오는 추가 신호는 같은 정답으로 보고 무시한다.
- 정답을 센 직후 저장소로 넘기기 전에 사용자가 다른 문제로 옮겨 가면, 그 정답은 넘기지 않고 버린다. 옮겨 갔다가 같은 문제로 되돌아온 경우에도 버린다.
- 문제 풀이 화면이 아닌 프로그래머스 화면에서는 어떤 변화가 있어도 아무 일도 일어나지 않는다.
- 이미 저장한 것과 똑같은 코드를 다시 제출한 경우, 정답을 세는 것까지는 그대로 일어나지만 알림도 기록도 커밋도 생기지 않는다. 규칙은 [같은 풀이 중복 방지](../common/duplicate-prevention.md)를 따른다.
- 저장소를 아직 연결하지 않았거나 자동으로 올리는 설정을 꺼 둔 경우, 정답을 세는 것까지는 그대로 일어나 알림은 보이지만 커밋은 생기지 않는다.

## Acceptance
- 문제 풀이 화면에서 정답 제출을 하면, 결과 창이 눈에 보이는 순간 저장소로 올리는 중이라는 알림이 한 번 보인다
- 정답 창이 떠 있는 동안 화면의 다른 곳을 건드리면 알림이 다시 보이지 않는다
- 결과 창을 닫은 뒤 코드를 바꿔 다시 정답을 받으면 알림이 다시 한 번 보인다
- 틀린 제출로 결과 창이 뜨면 알림이 보이지 않는다
- 코드 실행만 하면 알림이 보이지 않는다
- 정답 창이 이미 떠 있는 화면에서 확장 프로그램을 새로 켜면 알림이 보이지 않는다
- 문제 풀이 화면이 아닌 프로그래머스 화면을 열어 두면 알림이 보이지 않는다
- 새로고침 없이 다른 문제로 옮겨 가 정답을 받으면, 옮겨 간 문제 번호로 기록이 한 줄 남는다
- 한 번의 정답 제출 뒤 기록 목록을 열면 그 제출에 대한 줄이 정확히 하나만 있다

## 열린 질문
- 다른 코딩 사이트에서 프로그래머스 문제 화면으로 새로고침 없이 넘어온 첫 순간을 판정하지 않는 것은 의도된 결정인가, 아니면 고쳐야 할 누락인가? 이 동작 때문에 정답이 기록되지 않았다는 제보가 있으나 아직 재현되지 않았다.
- 같은 순간의 신호를 하나로 묶는 0.7초라는 값은 무엇을 근거로 정한 것인가? 이 값을 사용자가 체감하는 경우가 있는가?
- 결과 창을 닫은 뒤 두 번째 정답을 받는 흐름은 실제 제출로 확인된 적이 없다. 이 명세의 두 번째 계기는 코드에서 읽은 것이며, 실제로 그렇게 동작하는지 확인이 필요하다.
