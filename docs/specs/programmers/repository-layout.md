# 프로그래머스 풀이의 저장 위치와 목록

> **Description**: 프로그래머스 풀이가 사용자의 저장소 어디에 어떤 이름으로 쌓이고, 목록에 어떻게 보이는지를 정의한다. 무엇을 저장하는지는 [프로그래머스 풀이 확정](solution-snapshot.md)을 따른다.

## Goal
프로그래머스 풀이가 저장소에서 언어별로 정리되어 쌓이고, 한 장의 목록으로 한눈에 보이게 한다.

## Triggers
프로그래머스 정답이 저장소에 올라갈 때마다.

## Inputs
- 문제 번호와 문제 이름 — 사용자가 연 문제로 정해진다.
- 선택된 언어 — 사용자가 고른다.
- 풀이 코드 — 사용자가 쓴다.
- 문제 화면의 주소 — 목록에서 문제로 돌아가는 링크가 된다.
- 그 문제를 그 언어로 올린 것이 몇 번째인지 — 확장 프로그램이 센다.
- 어느 저장소의 어느 가지에 올릴지 — 사용자가 설정 화면에서 고른다.

## Outputs
- 저장소 최상위에 프로그래머스 전용 폴더가 생기고, 그 안에서 언어별로 폴더가 나뉜다.
- 풀이 파일 이름은 문제 번호와 문제 이름을 밑줄로 이은 형태이며, 언어에 맞는 확장자가 붙는다. 문제 이름의 한글은 그대로 남고, 빈칸과 기호는 밑줄로 바뀐다.
- 프로그래머스 폴더 안에 목록 문서가 생긴다. 문제 하나가 한 줄이고, 여러 언어로 푼 문제는 한 칸에 링크가 여럿 들어간다.
- **목록에는 난이도 칸이 없다.** 프로그래머스가 난이도를 제공하지 않기 때문이다.
- 목록 문서에서 확장 프로그램이 관리하는 구간은 표시로 감싸여 있고, 사용자가 그 밖에 직접 쓴 내용은 갱신할 때도 그대로 남는다.
- 프로그래머스 폴더 안 숨김 폴더에 목록의 원본 데이터 파일이 함께 쌓인다.
- 커밋 한 번에 풀이 파일, 목록 문서, 원본 데이터가 함께 바뀐다.
- 커밋 설명에는 사이트 이름, 문제 번호, 문제 이름, 언어와 몇 번째 풀이인지가 사람이 읽을 수 있는 한 줄로 들어간다.

## Edge cases
- 같은 문제를 두 언어로 풀면 목록에는 줄이 하나만 늘고, 그 줄의 링크 칸에 언어가 둘 들어간다.
- 같은 문제를 같은 언어로 다시 풀어 코드가 달라지면 파일은 새 내용으로 바뀌고, 몇 번째 풀이인지가 하나 올라간다.
- 문제 이름을 파일 이름으로 쓸 수 없으면 밑줄로 바뀌고, 그러고도 남는 글자가 없으면 정해진 기본 이름이 쓰인다.
- 문제 번호는 앞을 영으로 채우지 않고 화면에 보이는 그대로 쓴다.
- 목록에 남는 문제 링크에는 주소 뒤의 부가 표시가 붙지 않는다.
- 커밋 설명에 몇 번째 풀이인지를 적을 때 우물 정자 기호를 쓰지 않는다. 저장소에 등록된 다른 글의 번호로 잘못 이어지기 때문이다.
- 사용자가 목록 문서의 관리 구간 안을 손으로 고쳐 두면, 다음 커밋에서 그 구간은 다시 만들어져 손댄 내용이 사라진다.

## Acceptance
- 프로그래머스에서 정답을 받은 뒤 저장소를 열면, 프로그래머스 전용 폴더 안 언어별 폴더에 풀이 파일이 있다
- 그 파일 이름을 보면 문제 번호와 문제 이름이 밑줄로 이어져 있다
- 프로그래머스 목록 문서를 열면 난이도 칸이 없다
- 같은 문제를 두 언어로 풀고 목록 문서를 열면, 그 문제 줄은 하나이고 링크가 둘이다
- 목록 문서의 관리 구간 밖에 직접 글을 써 두고 새 풀이를 올리면, 써 둔 글이 그대로 남아 있다
- 같은 문제를 같은 언어로 두 번 풀고 커밋 설명을 보면, 두 번째 설명에 두 번째 풀이라는 표시가 들어 있다
- 목록 문서의 문제 링크를 누르면 그 문제 화면이 열린다

## 열린 질문
- 목록 문서의 관리 구간 안을 사용자가 고쳤을 때 그 내용이 사라지는 것을 사용자에게 미리 알릴 필요가 있는가?
- 숨김 폴더의 원본 데이터 파일은 사용자가 직접 볼 일이 없는데도 저장소에 남는다. 이것이 의도된 결정인가?
