# LeetCode 정답 감지

> **Description**: LeetCode 문제 화면에서 채점 결과가 정답으로 바뀐 순간을 언제 새로운 정답으로 세고 언제 세지 않는지를, 화면에서 관측되는 것만으로 정의한다. 무엇을 저장할지 정하는 동작은 [LeetCode 풀이 조회](submission-lookup.md)를 따른다.

## Goal
LeetCode에서 채점 결과가 정답으로 바뀐 순간을 한 번만 알아채, 그 풀이가 저장소로 넘어가기 시작하게 한다.

## Triggers
- 사용자가 LeetCode 문제 화면에서 제출한 뒤, 채점 중이라고 적혀 있던 자리의 글자가 그 자리에서 정답 문구로 바뀐 순간
- 정답 문구가 담긴 부분이 화면에 새로 나타난 순간

두 계기 모두 **이번 변화가 만들어낸 정답 문구**를 가리킨다. 화면에 이미 있던 정답 문구는 아무리 여러 번 다시 읽혀도 계기가 아니다.

## Inputs
- 지금 열려 있는 문제 화면의 주소 — 사용자가 어떤 문제를 열었는지로 정해진다. 주소가 LeetCode의 문제 주소이고 그 뒤에 문제 이름표가 붙어 있을 때만 감지 대상이다. 이 이름표는 정답 후보가 나올 때마다 그 시점의 주소에서 다시 읽는다.
- 이번에 바뀐 자리의 글자 — LeetCode가 정한다. 앞뒤 공백을 하나로 줄인 뒤 판정하며, 180자를 넘는 글은 결과 문구로 보지 않는다.
- 같은 순간에 온 신호를 하나로 묶는 시간 — 제품이 0.7초로 고정하며 사용자가 바꿀 수 없다.

정답으로 보는 글은 둘뿐이다. 정확히 "Accepted" 한 단어이거나, "Accepted" 뒤에 통과한 테스트 개수와 전체 개수가 붙은 결과 문구다. <!-- lint-ok -->

## Outputs
- 정답으로 셀 때: 저장소로 넘길 준비가 시작된다. 화면 구석에 저장소로 올리는 중이라는 알림이 뜨고, 뒤이어 성공 또는 실패 알림으로 바뀐다. 확장 프로그램의 기록 목록에 한 줄이 남고, 사용자가 연결한 저장소에 커밋이 하나 생긴다.
- 정답으로 세지 않을 때: 알림도, 기록도, 커밋도 생기지 않는다. LeetCode 서버에 무엇을 물어보는 일도 일어나지 않는다.
- 한 번의 정답에 대해 알림·기록·커밋은 각각 하나씩이다.

## Edge cases
- 오답, 실행 시간 초과, 메모리 초과, 컴파일 오류, 실행 오류, 채점 대기와 채점 중이라는 글이 섞여 있는 결과는 정답으로 세지 않는다. 그런 낱말이 하나라도 들어 있으면 같은 글에 "Accepted"가 함께 있어도 정답이 아니다. <!-- lint-ok -->
- 문제 화면에는 "Acceptance Rate", "Accepted Submissions", "Accepted Solutions" 같은 통계 문구가 늘 떠 있다. 이런 문구는 정답으로 세지 않는다. <!-- lint-ok -->
- 정확히 "Accepted" 한 단어만 있는 글은, 이번에 바뀐 자리에 글이 그것 하나뿐일 때만 정답으로 센다. 여러 조각의 글을 이어 붙여 만든 문장에서는 한 단어 일치를 받지 않는다. <!-- lint-ok -->
- **이미 푼 문제 화면에는 풀이 완료를 알리는 자리에도 정답 한 단어만 들어 있다.** 그 자리가 지켜보는 동안 새로 그려지면 제출하지 않았는데도 정답으로 센다. 문제 화면을 그냥 열기만 했을 때는 그 자리가 이미 그려진 뒤라 세지 않는 것이 확인됐고, 실제 사용 중에 이 일이 벌어지는 경로는 아직 확인되지 않았다.
- 숨겨진 자리에 들어 있는 글은 정답으로 세지 않는다.
- 확장 프로그램이 켜지는 순간 정답 문구가 이미 화면에 있으면 그 정답은 세지 않는다. 이미 지난 정답을 다시 올리지 않기 위해서다.
- 정답을 센 직후 0.7초 안에 들어오는 추가 신호는 같은 정답으로 보고 무시한다.
- 새로고침 없이 같은 사이트 안에서 다른 문제로 옮겨 가면, 옮겨 간 문제의 이름표로 다시 세기 시작하고 묶음 시간도 풀린다.
- 정답을 센 직후 넘기기 전에 사용자가 다른 문제로 옮겨 가면 그 정답은 버린다. 옮겨 갔다가 같은 문제로 되돌아온 경우에도 버린다.
- 문제 화면이 아닌 LeetCode 화면에서는 어떤 변화가 있어도 아무 일도 일어나지 않는다.
- 저장소를 아직 연결하지 않았거나 자동으로 올리는 설정을 꺼 둔 경우, 정답을 세는 것까지는 그대로 일어나 알림은 보이지만 LeetCode 서버에 물어보지도, 커밋을 만들지도 않는다.
- 채점 중에도 이 문제 화면은 계속 조금씩 바뀐다. 그래서 화면이 조용해지는 것은 채점이 끝났다는 뜻이 아니며, 채점 완료 판정에 쓰지 않는다.

## Acceptance
- 문제 화면에서 정답 제출을 하면, 채점 중이라는 글자가 정답으로 바뀌는 순간 저장소로 올리는 중이라는 알림이 한 번 보인다
- 정답 결과가 떠 있는 동안 화면의 다른 곳을 건드려도 알림이 다시 보이지 않는다
- 오답 제출을 하면 알림이 보이지 않는다
- 오답 제출을 한 뒤 기록 목록을 열면 그 제출에 대한 줄이 없다
- 이미 푼 문제 화면을 그냥 열어 두기만 하면 알림도 기록도 생기지 않는다
- 문제 화면이 아닌 LeetCode 화면을 열어 두면 알림이 보이지 않는다
- 새로고침 없이 다른 문제로 옮겨 가 정답을 받으면, 옮겨 간 문제로 기록이 한 줄 남는다
- 한 번의 정답 제출 뒤 기록 목록을 열면 그 제출에 대한 줄이 정확히 하나만 있다

## 열린 질문
- 이미 푼 문제의 풀이 완료 표시가 다시 그려져 정답으로 잘못 세지는 경로가 실제 사용 중에 존재하는가? 존재한다면 제출하지 않은 옛 풀이가 커밋되므로 판정 규칙에 화면 영역 조건을 넣어야 하는가?
- 같은 순간의 신호를 하나로 묶는 0.7초라는 값은 무엇을 근거로 정한 것인가? 사용자가 이 값을 체감하는 경우가 있는가?
- 결과 문구를 180자까지만 보는 것은 어떤 관찰에서 나온 값인가? 통과 개수가 아주 큰 문제에서도 이 길이로 충분한가?
- 결과가 두 번째 제출에서도 같은 방식으로 바뀌는지는 실제 제출로 확인된 적이 없다. 한 문제에서 정답을 연달아 두 번 받아 확인할 필요가 있다.
