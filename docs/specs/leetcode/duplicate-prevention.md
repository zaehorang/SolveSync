# LeetCode 같은 제출 중복 방지

> **Description**: 같은 제출이 두 번 저장되지 않게 막는 규칙과, 같은 코드를 다시 제출했을 때는 왜 커밋이 또 생기는지를 화면과 저장소에서 관측되는 것만으로 정의한다. 무엇이 하나의 제출인지는 [LeetCode 풀이 조회](submission-lookup.md)를 따른다.

## Goal
이미 저장한 제출이 다시 올라와도 저장소에 같은 커밋이 다시 쌓이지 않게 한다.

## Triggers
LeetCode 서버에서 제출을 가져온 뒤 저장소에 올리기 직전마다 매번 확인한다.

## Inputs
- 가져온 제출에 LeetCode가 붙여 둔 제출 번호 — LeetCode가 정하며, 제출할 때마다 새 번호가 붙는다.
- 문제 이름표와 그 제출의 언어 — 함께 묶어 하나의 열쇠를 만든다.
- 지금까지 저장소에 올리는 데 **성공한** 열쇠 목록 — 확장 프로그램이 기기 안에 보관한다.
- 지금 저장하는 중인 열쇠 목록 — 확장 프로그램이 기기 안에 보관하며 10분이 지나면 저절로 풀린다.

**코드 내용은 비교에 쓰지 않는다.** 세 사이트 가운데 LeetCode만 그렇다.

## Outputs
- 처음 보는 제출이면 저장소에 올리는 작업이 그대로 진행된다.
- 이미 올린 제출이면 **아무 일도 일어나지 않는다.** 알림도 뜨지 않고, 기록 목록에도 줄이 늘지 않으며, 커밋도 생기지 않는다.
- 성공한 목록에는 저장소에 커밋이 실제로 만들어진 뒤에만 추가된다.
- 성공한 목록에는 그때 만들어진 커밋과 저장된 파일 위치도 함께 남는다.

## Edge cases
- **같은 코드를 그대로 다시 제출해 정답을 받으면 커밋이 또 생긴다.** 제출 번호가 새로 붙기 때문이다. 저장소의 파일 내용은 그대로지만 목록과 커밋 설명의 풀이 회차가 하나 올라간다.
- 같은 제출을 두 번 집어 든 경우에만 막힌다. 정답 신호가 두 번 들어왔는데 그 사이 LeetCode에 새 제출이 없었을 때가 그렇다.
- 앞의 것이 아직 올라가는 중인데 같은 제출이 또 들어오면 뒤엣것은 조용히 버려진다. 앞의 것이 10분 안에 끝나지 않으면 그 잠금은 풀린다.
- 저장소에 올리다가 실패하면 성공한 목록에 남지 않는다. 그래서 다시 시도하면 그때는 실제로 다시 올라간다.
- 이미 푼 문제를 열었을 때 잘못 감지되는 경우가 있더라도, 그 문제의 마지막 정답 제출을 이 기기에서 이미 저장한 적이 있으면 여기서 막힌다. 확장 프로그램을 설치하기 전에 푼 문제만 이 방어를 지나친다.
- 성공한 목록은 지워지거나 오래됐다고 버려지지 않고 계속 쌓인다.
- 확장 프로그램을 지우고 다시 설치하면 성공한 목록도 함께 사라진다. 그 뒤에는 예전에 올렸던 제출도 처음 보는 것으로 취급된다.
- 이 확장 프로그램이 다루지 않는 언어로 한 제출은 이 확인에 이르기 전에 걸러진다.

## Acceptance
- 정답을 받은 뒤 코드를 그대로 두고 다시 제출해 정답을 받으면, 새 커밋이 하나 더 생긴다
- 코드를 그대로 두고 다시 제출해 정답을 받은 뒤 커밋 설명을 보면, 풀이 회차가 하나 올라가 있다
- 저장소 연결이 끊긴 채로 정답을 받아 실패한 뒤 연결을 고치고 같은 문제를 다시 제출하면, 이번에는 커밋이 생긴다
- 한 번의 정답 제출로 알림이 두 번 뜨는 경우에도 기록 목록에는 줄이 하나만 남는다
- 이미 저장한 적이 있는 문제 화면을 다시 열어 두기만 하면, 커밋이 생기지 않는다

## 열린 질문
- 같은 코드를 다시 제출했을 때 파일 내용이 같은데도 커밋이 하나 더 생기는 것은 의도된 결정인가? 다른 두 사이트에서는 코드가 같으면 커밋이 생기지 않아 같은 저장소 안에서 규칙이 갈린다.
- 성공한 열쇠 목록은 개수 제한도 보관 기간 제한도 없이 계속 쌓인다. 오래 쓴 기기에서 이 목록이 커지는 것이 문제가 되는가?
- 저장하는 중이라는 잠금이 10분 뒤 풀리는 것은 무엇을 근거로 정한 값인가? 그 사이 브라우저를 껐다 켜면 잠금이 남아 있는 동안 같은 제출을 저장할 수 없는데, 사용자에게 그 사실이 보이지 않는다.
