# LeetCode 저장 실패 다시 시도

> **Description**: LeetCode 풀이를 가져오는 데까지는 성공했지만 저장소에 올리다가 실패했을 때, 다시 제출하지 않고 버튼 한 번으로 다시 올릴 수 있게 하는 동작을 정의한다. 가져오는 데 실패한 경우는 [LeetCode 풀이를 조회하지 못했을 때](lookup-failure.md)를 따른다.

## Goal
저장소에 올리다가 실패한 LeetCode 풀이를, 문제를 다시 풀지 않고 버튼 한 번으로 다시 올릴 수 있게 한다.

## Triggers
- 저장소에 올리는 마지막 단계에서 실패하면, 그때의 풀이 한 벌이 기기 안에 보관된다.
- 사용자가 기록 목록의 실패한 줄에서 다시 시도 버튼을 누르면 그 풀이 한 벌로 다시 올린다.
- 같은 문제의 실패가 여러 줄로 묶여 있으면 묶음째 다시 시도할 수도 있다.

## Inputs
- 실패했을 때 확정돼 있던 풀이 한 벌 — 문제 번호, 제목, 난이도, 언어, **LeetCode에서 가져온 코드**, 올릴 저장소와 가지, 저장할 파일 위치가 들어 있다. 사용자가 다시 시도를 누를 때까지 기기 안에 그대로 남는다.
- 어떤 실패였는지 — 다시 시도할 만한 실패인지가 여기서 갈린다.
- GitHub 연결 — 사용자가 설정 화면에서 만든다. 다시 시도하는 순간에도 연결돼 있어야 한다.

## Outputs
- 실패한 줄에 다시 시도 버튼이 붙는다. 누르면 다시 시도 중이라는 알림이 뜨고, 성공하면 저장소에 커밋이 하나 생기며 기록 목록에 성공한 줄이 새로 남는다.
- 성공한 뒤에는 보관하던 풀이 한 벌이 지워진다. 그 안의 코드도 함께 사라진다.
- 다시 시도해도 실패하면 새 실패 줄이 남고, 풀이 한 벌은 시도 횟수만 하나 올라간 채 그대로 남는다.
- 다시 올릴 때는 저장소의 현재 내용을 다시 읽어 목록과 커밋 설명을 새로 만든다. 실패한 사이에 저장소가 바뀌었어도 그 변화 위에 얹힌다.
- 보관하는 풀이는 최대 20벌이고 최대 7일이다. 넘치면 오래된 것부터 사라지고, 7일이 지난 것은 저절로 사라진다.
- 이 보관에 코드가 들어간다는 사실은 설정 화면과 확장 프로그램 창에 안내로 적혀 있다.

## Edge cases
- **가져오는 데 실패한 경우에는 풀이 한 벌이 만들어지지 않는다.** 올릴 코드가 없기 때문이다. 그때는 다시 시도 버튼이 나타나지 않는다.
- 저장소의 기존 목록 파일을 읽는 단계에서 실패한 경우에도 풀이 한 벌이 만들어지지 않는다. 다시 시도 버튼 없이 실패 줄만 남는다.
- 다시 시도해도 결과가 달라지지 않는 실패(예: 보호된 가지에 올리려 한 경우)에서는 풀이 한 벌이 남아 있어도 버튼이 나타나지 않고, 이 실패는 다시 시도할 수 없다는 안내가 대신 보인다.
- 7일이 지나 사라진 뒤에 다시 시도를 누르면, 다시 시도할 재료가 없다는 실패 줄이 하나 더 남는다. 그 줄에는 어떤 문제였는지도 남지 않는다.
- 다시 시도하는 사이에 같은 제출이 이미 저장됐다면 아무 일도 일어나지 않고 보관하던 풀이만 조용히 사라진다.
- 다시 시도할 때 GitHub 연결이 끊겨 있으면 다시 실패하고, 로그인이 필요하다는 실패 줄이 남는다.
- 앞의 시도가 아직 끝나지 않았는데 다시 시도를 또 누르면 뒤엣것은 조용히 버려진다.

## Acceptance
- 저장소에 올리는 도중 실패한 뒤 기록 목록을 열면, 그 줄에 다시 시도 버튼이 보인다
- 실패한 원인을 고치고 다시 시도 버튼을 누르면, 저장소에 커밋이 하나 생긴다
- 다시 시도가 성공한 뒤 기록 목록을 열면, 성공한 줄이 새로 하나 보인다
- 다시 시도가 성공한 뒤 같은 줄에서 다시 시도 버튼을 찾으면, 버튼이 없다
- 다시 시도가 또 실패하면 실패한 줄이 하나 더 늘어난다
- 풀이를 가져오는 데 실패한 줄을 열면 다시 시도 버튼이 없다
- 설정 화면의 보안 안내를 열면 실패한 풀이의 코드가 기기에 잠시 보관될 수 있다는 문장이 보인다

## 열린 질문
- 보관 한도인 20벌과 7일은 무엇을 근거로 정한 값인가? 한도를 넘겨 조용히 사라진 풀이가 있다는 사실이 사용자에게 보이지 않는데, 알릴 필요가 있는가?
- 저장소의 기존 목록 파일을 읽다가 실패한 경우에도 올릴 코드는 이미 확정돼 있는데 다시 시도 버튼이 없다. 이것은 의도된 구분인가?
- 다시 시도할 만하다고 표시되는 실패 가운데 풀이 한 벌이 없는 것들이 있다. 표시와 실제 버튼 유무가 어긋나는 것을 사용자가 어떻게 받아들이는가?
