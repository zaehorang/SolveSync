# LeetCode 풀이를 확보하지 못했을 때

> **Description**: 정답은 받았지만 LeetCode 서버에서 풀이를 가져오지 못했을 때 사용자가 무엇을 보게 되는지를 정의한다. 조회 자체는 [LeetCode 풀이 확보](solution-source.md)를 따른다.

## Goal
정답을 받았는데 LeetCode 서버에서 풀이를 가져오지 못한 경우, 조용히 넘어가지 않고 사용자가 그 사실과 이유를 알게 한다.

## Triggers
- LeetCode 로그인이 없거나 만료돼 서버가 제출 기록을 돌려주지 않을 때
- 서버가 문제 정보나 제출 기록을 돌려주지 못하거나, 돌려준 내용에서 필요한 값을 찾지 못할 때
- 그 문제의 정답 제출을 하나도 찾지 못했을 때
- 가져온 제출의 코드가 비어 있을 때
- 조회하는 동안 인터넷 연결이 끊겼을 때

## Inputs
- 서버가 돌려준 응답 — LeetCode가 정한다. 로그인을 요구하는 응답인지, 그 밖의 실패인지, 아예 닿지 못한 것인지에 따라 사용자가 보는 문구가 갈린다.
- 주소에서 읽은 문제 이름표 — 실패 기록에도 이것만 남는다.

## Outputs
- 세 갈래 가운데 하나로 알림이 뜬다. 로그인이 필요할 때는 "LeetCode login required.", 조회가 실패했을 때는 "Could not read the LeetCode submission.", 서버에 닿지 못했을 때는 "Network request failed."가 보인다. <!-- lint-ok -->
- 기록 목록에 실패한 줄이 하나 남고 커밋은 생기지 않는다.
- 실패한 줄을 열면 어떤 실패였는지 나타내는 짧은 이름과, LeetCode가 돌려준 설명이 함께 보인다.
- **실패한 줄에 다시 시도하는 버튼이 없다.** 대신 설정을 확인하거나 다시 제출하라는 안내가 붙는다.
- 실패한 줄에는 문제 제목도 언어도 남지 않는다. 주소에서 읽은 문제 이름표만 남는다. 그 둘은 서버에 물어봐야 알 수 있는데 그 물음이 실패했기 때문이다.
- 다시 올릴 코드를 어디에도 보관하지 않는다.

## Edge cases
- 로그인이 필요한 실패는 다시 시도해도 결과가 달라지지 않는 실패로 표시된다. 사용자가 LeetCode에 다시 로그인한 뒤 문제를 다시 제출해야 한다.
- 조회 실패는 다시 시도할 만한 실패로 표시되지만, 다시 시도할 재료가 남아 있지 않아 버튼은 나타나지 않는다.
- 오답이나 실행만 한 경우에는 조회를 시작하지 않으므로 이 실패도 생기지 않는다. 오답 뒤에 조회 실패 알림이 뜬다면 지난 정답을 다시 집어 들었다는 뜻이다.
- 실패해도 그 정답을 처리했다는 사실은 남지 않는다. 같은 문제를 다시 제출하면 중복으로 걸리지 않고 다시 조회한다.
- 저장소를 아직 연결하지 않았거나 자동으로 올리는 설정을 꺼 둔 경우는 이 실패가 아니다. 그때는 조회를 시작하기 전에 설정을 확인하라는 다른 안내가 보인다.
- 조회는 성공했지만 저장소에 올리다가 실패한 경우도 이 실패가 아니다. 그때는 다시 시도할 수 있으며 규칙은 [LeetCode 저장 실패 다시 시도](retry.md)를 따른다.

## Acceptance
- LeetCode에서 로그아웃한 채 정답을 받으면, 로그인이 필요하다는 알림이 보인다
- 로그아웃한 채 정답을 받은 뒤 저장소를 열면, 새 커밋이 없다
- 로그아웃한 채 정답을 받은 뒤 기록 목록을 열면, 실패한 줄이 하나 남아 있다
- 조회에 실패한 줄을 기록 목록에서 열면, 다시 시도하는 버튼이 없다
- 조회에 실패한 줄을 기록 목록에서 열면, 다시 제출하라는 안내가 보인다
- 조회에 실패한 줄을 보면 문제 제목 자리에 주소에서 읽은 문제 이름표가 들어 있다
- 다시 로그인한 뒤 같은 문제를 다시 제출해 정답을 받으면, 이번에는 커밋이 하나 생긴다

## 열린 질문
- 조회 실패는 다시 시도할 만한 실패로 표시되는데 다시 시도할 버튼은 없다. 표시와 실제가 어긋나는 것은 의도인가, 아니면 조회부터 다시 하는 재시도 경로가 빠진 것인가?
- 실패한 줄에 문제 제목이 남지 않아 목록에서 어떤 문제였는지 알아보기 어렵다. 문제 화면의 제목을 보조 수단으로 함께 남길 필요가 있는가?
- 로그인이 필요한 실패와 그 밖의 실패를 가르는 기준에는 서버가 돌려준 설명에 특정 낱말이 들어 있는지를 보는 부분이 있다. LeetCode가 문구를 바꾸면 갈림이 뒤집히는데, 이 취약함이 감수된 것인가?
