# SWEA 풀이를 읽지 못했을 때

> **Description**: 정답은 받았지만 풀이를 저장소에 올릴 수 없을 때 사용자가 무엇을 보게 되는지를 정의한다. 코드를 가져오는 과정은 [SWEA 풀이 코드 가져오기](code-retrieval.md)를 따른다.

## Goal
정답을 받았는데 풀이를 저장소에 올리지 못한 경우, 조용히 넘어가지 않고 사용자가 그 사실을 알게 한다.

## Triggers
- 정답을 센 뒤 편집기의 코드를 끝내 가져오지 못했거나 가져온 코드가 비어 있을 때
- 정답을 센 뒤 문제 이름이나 고른 언어를 화면에서 읽지 못했을 때

## Inputs
- 정답을 센 순간 고정한 값들과 뒤이어 도착한 코드 — 그 안에 빠진 것이 있는지가 판단 근거다.
- 이 확장 프로그램이 다루는 언어 목록 — 제품이 정하며 사용자가 바꿀 수 없다. 이 사이트에서 고를 수 있는 언어는 셋뿐이고 셋 모두 목록에 들어 있다.

## Outputs
- 화면 구석에 실패했다는 알림이 뜨고, 편집기의 코드를 읽지 못했다는 안내가 함께 보인다.
- 기록 목록에 실패한 줄이 하나 남고, 커밋은 생기지 않는다.
- 실패한 줄에도 어느 문제였는지 알 수 있도록 읽어 낸 만큼의 문제 번호와 이름이 남는다.
- **다시 시도하는 버튼을 제공하지 않는다.** 다시 올리려면 사용자가 문제를 다시 제출해야 한다.
- 실패한 줄을 펼치면 다시 시도할 수 있는 자료가 남아 있지 않다는 안내가 함께 보인다.

## Edge cases
- 코드가 공백이나 줄바꿈만 있으면 비어 있는 것으로 본다.
- 문제 이름을 읽지 못한 경우에는 실패 줄의 이름 자리가 비어 있고 번호만 남는다.
- 화면에서 고를 수 있는 세 언어는 모두 다루는 언어이므로, **이 사이트에서는 다루지 않는 언어라는 안내가 실제로 보이지 않는다.** 사이트가 언어를 더 늘리면 그때부터 보이기 시작한다.
- 저장소를 아직 연결하지 않았거나 자동으로 올리는 설정을 꺼 둔 경우는 이 실패가 아니다. 그때는 설정을 확인하라는 다른 안내가 보인다.
- 실패해도 정답을 셌다는 사실은 남지 않는다. 같은 풀이를 다시 제출하면 중복으로 걸리지 않고 다시 시도된다. 다만 다시 제출하는 만큼 문제당 남은 제출 횟수가 줄어든다.
- 실패한 뒤 같은 문제를 다시 제출해 이번에는 제대로 읽히면, 그 제출은 평소대로 커밋이 된다.
- 코드를 기다리는 동안 화면이 사라진 경우에는 이 실패조차 기록되지 않는다. 기록 목록에 아무 줄도 남지 않는다.

## Acceptance
- 풀이를 읽지 못해 실패한 줄을 기록 목록에서 열면, 다시 시도하는 버튼이 없다
- 풀이를 읽지 못해 실패하면 저장소에 새 커밋이 생기지 않는다
- 실패한 줄을 기록 목록에서 보면, 어느 문제였는지 알 수 있는 번호가 함께 보인다
- 실패한 직후 화면 구석에 실패했다는 알림이 보인다
- 실패한 뒤 코드를 그대로 두고 같은 문제를 다시 제출해 정답을 받으면, 이번에는 커밋이 하나 생긴다
- 이 사이트에서 고를 수 있는 세 언어 중 아무거나 골라 정답을 받으면, 다루지 않는 언어라는 안내가 보이지 않는다

## 열린 질문
- 다시 시도하는 버튼을 제공하지 않는 것은 편집기 내용을 보관하지 않기로 한 결정 때문인가? 사용자에게 "다시 제출하세요"라는 안내가 더 필요하지 않은가?
- 실패했을 때 보이는 안내 문구가 화면 언어 설정과 무관하게 영어로 나온다. 의도된 것인가?
- 편집기의 코드를 읽지 못하는 상황이 실제 사용 중에 어떤 경우에 생기는지 확인된 적이 있는가? 지금까지 확인된 것은 편집기 자체가 없는 화면을 만들어 본 경우뿐이다.
- 문제당 제출 횟수에 상한이 있는 사이트인데, 실패 뒤 재제출을 요구하는 것이 사용자에게 실제 비용이 된다. 다른 방법을 제공해야 하는가?
