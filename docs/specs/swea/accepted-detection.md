# SWEA 정답 감지

> **Description**: SW Expert Academy 풀이 화면에서 정답을 받은 순간을 언제 새로운 정답으로 세고 언제 세지 않는지를, 화면에서 관측되는 것만으로 정의한다. 어느 문제의 정답인지 가려내는 규칙은 [SWEA 어느 문제를 푼 것인지 가려내기](problem-identity.md)를 따른다.

## Goal
SW Expert Academy에서 정답을 받은 순간을 한 번만 알아채, 그 풀이가 저장소로 넘어가기 시작하게 한다.

## Triggers
- 사용자가 풀이 화면에서 채점 제출을 한 뒤, 결과를 알리는 작은 창이 화면에 **새로 나타나고** 그 안의 글이 "축하합니다. Pass입니다."로 시작하는 순간 <!-- lint-ok -->
- 이미 화면에 있던 글자가 그 문구로 **바뀌는** 순간. 바뀌기 전에 이미 그 문구였다면 계기가 아니다

두 계기 모두 **이번에 화면이 달라진 부분**만 본다. 이미 떠 있는 정답 창은 아무리 다시 살펴봐도 계기가 되지 않는다.

## Inputs
- 지금 열려 있는 풀이 화면 — 사용자가 어떤 문제를 열었는지로 정해진다. SW Expert Academy는 모든 문제가 같은 주소를 쓰므로 주소만으로는 문제를 구분할 수 없고, 화면 안에 들어 있는 문제 식별 값으로 구분한다. 그 값을 읽지 못하면 이 화면은 감지 대상이 아니다.
- 결과 창에 적히는 글 — SW Expert Academy가 정한다. 앞뒤 공백을 정리했을 때 "축하합니다. Pass입니다."로 **시작하면** 정답으로 본다. 뒤에 다른 문구가 더 붙어 있어도 된다. <!-- lint-ok -->
- 결과 글의 길이 — 180자를 넘는 글은 결과 문구로 보지 않는다. 제품이 정하며 사용자가 바꿀 수 없다.
- 같은 순간에 들어온 신호를 하나로 묶는 시간 — 제품이 0.7초로 고정하며 사용자가 바꿀 수 없다.

## Outputs
- 정답으로 셀 때: 화면 구석에 저장소로 올리는 중이라는 알림이 뜨고, 뒤이어 성공 또는 실패 알림으로 바뀐다. 확장 프로그램의 기록 목록에 한 줄이 남고, 사용자가 연결한 저장소에 커밋이 하나 생긴다.
- 정답으로 세지 않을 때: 알림도, 기록도, 커밋도 생기지 않는다. 화면에는 SW Expert Academy가 원래 보여주는 것 말고 아무 변화가 없다.
- 한 번의 정답에 대해 알림·기록·커밋은 각각 하나씩이다.
- 정답을 센 사실 자체는 어디에도 남지 않는다. 저장소에 커밋이 실제로 만들어진 뒤에만 기록이 남는다.

## Edge cases
- 틀린 제출은 같은 모양의 창을 쓰지만 글이 "오답"으로 시작한다. 이때는 아무 일도 일어나지 않는다. <!-- lint-ok -->
- 컴파일이 되지 않아 채점 전에 거부된 제출은 글이 "제출 오류"로 시작한다. 이때도 아무 일도 일어나지 않는다. <!-- lint-ok -->
- 제출하지 않고 코드만 실행한 경우에는 결과 창 자체가 뜨지 않고 화면 아래 출력 영역에만 결과가 쌓인다. 아무 일도 일어나지 않는다.
- 임시저장은 저장되었다는 창을 띄우지만 정답 문구가 아니므로 아무 일도 일어나지 않는다.
- 로그인이 풀린 상태에서는 세션이 만료되었다는 창만 뜨고 아무 일도 일어나지 않는다. 이때는 요청 자체가 수행되지 않은 것이므로, 아무 일도 일어나지 않은 이유가 감지 때문인지 요청이 안 나갔기 때문인지 화면만 보고는 구분되지 않는다.
- 제출 버튼을 누르면 채점 전에 제출 횟수가 하나 줄어든다는 확인 창이 먼저 뜬다. 이 창은 정답 문구가 아니므로 아무 일도 일어나지 않는다.
- 정답 창이 이미 떠 있는 동안 화면의 다른 곳이 바뀌어도 같은 정답을 다시 세지 않는다.
- 확장 프로그램이 켜지는 순간 정답 창이 이미 떠 있으면 그 정답은 세지 않는다.
- 화면에서 숨겨져 있는 자리에 정답 문구가 들어와도 세지 않는다.
- 정답을 센 직후 0.7초 안에 들어오는 추가 신호는 같은 정답으로 보고 무시한다.
- 정답 창의 확인을 눌러 창이 화면에서 사라져도, 이미 세어진 정답은 취소되지 않는다. 정답은 센 즉시 저장소 쪽으로 넘어가기 때문이다.
- 화면 안의 문제 식별 값을 읽지 못하는 화면에서는 정답 문구가 나타나도 아무 일도 일어나지 않는다.
- 풀이 화면이 아닌 SW Expert Academy 화면에서는 어떤 변화가 있어도 아무 일도 일어나지 않는다.
- 저장소를 아직 연결하지 않았거나 자동으로 올리는 설정을 꺼 둔 경우, 정답을 세는 것까지는 그대로 일어나 알림은 보이지만 커밋은 생기지 않는다.
- 이미 저장한 것과 똑같은 코드를 다시 제출한 경우, 정답을 세는 것까지는 그대로 일어나지만 알림도 기록도 커밋도 생기지 않는다. 규칙은 [같은 풀이 중복 방지](../common/duplicate-prevention.md)를 따른다.

## Acceptance
- 풀이 화면에서 정답 제출을 하면, 정답 창이 뜨는 순간 저장소로 올리는 중이라는 알림이 한 번 보인다
- 정답 창이 떠 있는 동안 화면의 다른 곳을 건드리면 알림이 다시 보이지 않는다
- 틀린 제출로 결과 창이 뜨면 알림이 보이지 않는다
- 컴파일이 되지 않는 코드를 제출해 결과 창이 뜨면 알림이 보이지 않는다
- 제출하지 않고 코드 실행만 하면 알림이 보이지 않는다
- 임시저장을 하면 알림이 보이지 않는다
- 정답 창이 이미 떠 있는 화면에서 확장 프로그램을 새로 켜면 알림이 보이지 않는다
- 풀이 화면이 아닌 SW Expert Academy 화면을 열어 두면 알림이 보이지 않는다
- 한 번의 정답 제출 뒤 기록 목록을 열면 그 제출에 대한 줄이 정확히 하나만 있다
- 정답 창이 뜬 직후 곧바로 확인을 누르면, 기록 목록에 그 제출에 대한 줄이 남는다

## 열린 질문
- 같은 순간의 신호를 하나로 묶는 0.7초라는 값은 무엇을 근거로 정한 것인가? 사용자가 이 값을 체감하는 경우가 있는가?
- 결과 글을 180자까지만 결과 문구로 보는 기준은 무엇을 근거로 정한 것인가?
- 정답 창의 확인을 눌렀을 때 화면이 통째로 다시 불러와지는지는 아직 확인되지 않았다. 사용자 제보만 있고 재현된 적이 없다. 확인이 필요한가?
- 정답 창 앞에 제목 줄이 붙는 형태로 SW Expert Academy가 화면을 바꾸면 정답 문구가 문장 맨 앞에 오지 않게 된다. 이때 감지가 멈추는 쪽으로 동작하는 것이 맞는가?
